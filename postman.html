Express Backend – Postman Reference

A walkthrough for testing every endpoint of the demo backend with Postman.

Base URL: http://localhost:3001

Before you start
  1. Start the backend: cd backend && npm run dev.
  2. Open Postman and create a new request (File → New → HTTP Request).
  3. Pick the HTTP method from the dropdown (GET, POST, PUT, PATCH, DELETE).
  4. Paste the full URL (e.g. http://localhost:3001/posts).
  5. For requests with a body: go to Body → raw → JSON and paste the JSON.
  6. Click Send. Watch the backend terminal — every hit logs the method, URL, body, and result.
Header reminder: Postman adds the Content-Type: application/json header automatically when you pick raw → JSON. If you use raw → Text, you must set it manually under the Headers tab.

Endpoints

GET /posts

List every post currently in memory.

In Postman
MethodGET
URLhttp://localhost:3001/posts
BodyNone
HeadersNone required
Expected response (200 OK)
[
  { "id": 1, "userId": 1, "title": "Hello world", "body": "This is the first post." },
  { "id": 2, "userId": 1, "title": "Express demo", "body": "Built with TypeScript." },
  { "id": 3, "userId": 2, "title": "JSON & APIs", "body": "Lecture sample post." }
]
GET /posts/:id

Fetch a single post by its id.

In Postman

POST /posts

Create a new post. The server assigns the next available id.

In Postman
MethodPOST
URLhttp://localhost:3001/posts
HeadersContent-Type: application/json (auto-set with raw → JSON)
Bodyraw → JSON (see below)
Request body
{
  "title": "New Post",
  "body": "Hello from Postman",
  "userId": 1
}
Expected response (201 Created)
{ "id": 4, "userId": 1, "title": "New Post", "body": "Hello from Postman" }
If a required field is missing (400)
{ "error": "title, body, and userId are required" }
PUT /posts/:id

Replace the post with the given id. All three fields are required. If the id does not exist, the post is created.

In Postman
MethodPUT
URLhttp://localhost:3001/posts/1
HeadersContent-Type: application/json
Bodyraw → JSON (see below)
Request body (all fields required)
{
  "title": "Replaced title",
  "body": "Full replacement",
  "userId": 1
}
Expected response (200 OK)
{ "id": 1, "userId": 1, "title": "Replaced title", "body": "Full replacement" }
If the id did not exist, you'll get 201 Created instead of 200 OK, with the same JSON body.
PATCH /posts/:id

Partially update the post with the given id. Send only the fields you want to change — everything else stays the same.

In Postman
MethodPATCH
URLhttp://localhost:3001/posts/1
HeadersContent-Type: application/json
Bodyraw → JSON (any subset of fields)
Request body (only what you want to change)
{ "title": "Patched title" }
Expected response (200 OK)
{ "id": 1, "userId": 1, "title": "Patched title", "body": "This is the first post." }
If the id does not exist (404)
{ "error": "Post 999 not found" }

Status code cheat sheet

CodeWhen you'll see it
200 OKSuccessful GET / PATCH / DELETE / PUT (when post existed).
201 CreatedSuccessful POST, or PUT against an id that didn't yet exist.
400 Bad RequestPOST or PUT missing one of title, body, userId.
404 Not FoundGET / PATCH / DELETE against an id that doesn't exist.

Suggested testing order

  1. GET /posts — confirm the seed data (3 posts).
  2. POST /posts — create a new one, note the returned id.
  3. GET /posts/:id — fetch the post you just created.
  4. PATCH /posts/:id — change only the title, see the rest stays.
  5. PUT /posts/:id — replace it entirely.
  6. DELETE /posts/:id — remove it.
  7. GET /posts again — confirm it's gone.

Tip: keep the backend terminal visible while you test. Every request prints a timestamped log with the method, URL, parsed body, and the action taken.
